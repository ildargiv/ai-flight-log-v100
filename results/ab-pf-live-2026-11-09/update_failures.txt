## 2. `--start-again` chose the wrong profile

Immediately after the successful update, the live server on port 8080 was 0.1.59 but
served through the wrong run config:

```text
serve.server --engine strata --config <launch>/iq3_xxs-256k.json --host 0.0.0.0 --port 8080
```

Engine process env showed:

```text
STRATA_RUNTIME_PROFILE=launch-iq3_xxs-256k
STRATA_ROUTE_PRIOR=1.5
```

and lacked the profile sm_70 keys and `STRATA_PF_WMMA`. The `iq3_xxs-256k` engine started
line also lacked `--conversation-cache-*` and `--prompt-cache`. It was stopped and the
correct profile was started fresh.

## 3. PF_WMMA dropped by auto-start/migration

After restarting 0.1.59 with the correct profile and proof, a later `start-again` path
left `lan-open.json` env with only:

```json
{
 "STRATA_ARGMAX_ROWS_SM70": "1",
 "STRATA_FUSE_DECODE": "1",
 "STRATA_GR_NORM_FAST": "1",
 "STRATA_SM70_TABLE": "1"
}
```

and live environ had no `STRATA_PF_WMMA`. Fixed by explicit fresh launch:

```bash
ulimit -l 8192
strata launch --preset lan-open --yes --no-tui --set STRATA_PF_WMMA=1
```

Proof after final start contains `STRATA_PF_WMMA=1`.
